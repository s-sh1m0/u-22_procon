# DESIGN.md — DiffGraph. UI/UX 設計

> 本ドキュメントはデザイン・UI/UX に関する方針のみをまとめたもの。詳細は今後の検証で変わり得るため、確定事項ではなく **設計の出発点** として扱う。

---

## 1. デザイン原則

- **構造で読ませる**: 変更行の羅列ではなく、モジュールの関係として PR を見せる
- **語彙を統一**: 案・画面が違ってもノード／エッジ／クラスタ色の表現は揃える
- **密度に強い**: 大規模PR（30+ファイル）でも一覧性を維持
- **静かな UI**: 装飾よりも情報の整理を優先、アニメは控えめ

---

## 2. ビジュアル言語

### 2.1 トーン
モダン SaaS — 明るくクリーン、装飾控えめ、密度は中〜高。

### 2.2 カラー（暫定）
| 用途 | 値 |
|---|---|
| 背景 | `#fafaf9` / `#f5f5f4` |
| 罫線 | `#e7e5e4` / `#d6d3d1` |
| インク | `#1c1917` → `#44403c` → `#78716c` |
| ブランド | teal `#0f766e` + `#ccfbf1` |
| 追加 | `#16a34a` / bg `#dcfce7` |
| 削除 | `#dc2626` / bg `#fee2e2` |
| 修正 | `#d97706` / bg `#fef3c7` |
| リファクタ | `#7c3aed` / bg `#ede9fe` |

→ クラスタ色は diff 定番（緑/赤）+ 補色（橙/紫）。**色の意味は全画面で統一**。

### 2.3 タイポグラフィ
- UI: **Inter Tight** 400/500/600（見出しは letter-spacing マイナス）
- コード/数値: **JetBrains Mono** 400/500
- 本文は `text-wrap: pretty`

### 2.4 形状・余白
- 角丸: ノード 6px / カード 10〜12px / バッジ 99px（pill）
- 影: 軽め（`0 1px 2px` ベース、フォーカス時のみ強）
- パディング: 14〜18px が基準、密度切替で 8〜24px に

### 2.5 変更余地
- ダークモード未実装
- ブランド名・ロゴ（DiffGraph.）は仮
- アクセント色 teal は他色に振る選択肢あり

## 4. 分類軸（4-way クラスタリング）

UI の語り口を決める核。現時点は「変更の種類」で切る。

| クラスタ | 意味 | 色 | アイコン |
|---|---|---|---|
| 追加 | 新規モジュール | 緑 | + |
| 削除 | 削除モジュール | 赤 | − |
| 修正 | ロジック変更を含む | 橙 | ~ |
| リファクタ | 振る舞い保存・構造変更のみ | 紫 | ↻ |

### 4.1 補助軸（レイヤ）
依存方向の整合性を見せるため `ui` / `domain` / `data` / `infra` を併用。

### 4.2 軸変更の余地
- リスク度（高/中/低/情報）
- 影響範囲ベース（ローカル/モジュール/横断/破壊的）
- レビュー優先度

UI 側は「**現在の軸 + 件数集計**」のみを抽象として持ち、軸定義は差し替え可能にする。

## 5. 結果ビューの並走案

1つに収束させず、役割ごとの使い分けもあり得る。

### 案A · クラシック階層DAG + 右パネル
- 上から下に UI → Domain → Data → Infra
- ノード = モジュール、エッジ色 = 起点クラスタ色
- 右にサイドパネルで diff / 関数 / 統計
- 強み: 既視感、依存の流れが直感的
- 弱み: ノード数が増えるとレイヤ内が混雑

### 案B · スイムレーン
- 横軸 = 4クラスタ、縦軸 = 4レイヤ
- レーン内エッジは実線、跨ぎは破線
- 強み: クラスタごとの規模が一目、跨ぎ依存＝注目点
- 弱み: 依存方向が読みづらい

### 案C · ダッシュボード型サマリー
- 上部に4クラスタ統計カード + 4象限グリッド
- カードに関数変更スパークバー
- 強み: 件数・規模感を最初に伝える、密度に強い
- 弱み: 依存関係そのものは見えない

### 案D · 影響範囲ヒートマップ
- 変更モジュール起点に hop 別で波紋を可視化
- 0=変更元 / 1=直接 / 2=2hop / 3+=遠い
- モード切替: 「変更全体」/「選択モジュール起点」
- 強み: マージ時のリスクが見える
- 弱み: コールグラフ精度に依存

## 6. 共通 UI コンポーネント

案を超えて再利用するため、見た目の語彙を固定。

- **トップバー**: PR メタ情報 + +/- 行数 + 著者アバター
- **ノード**: 角丸矩形 + クラスタ色の左バー + 名前 + +/- + 関数数
- **エッジ**: ベジェ曲線 + 起点クラスタ色 + 矢印マーカー
- **クラスタ凡例**: 右下フロート、配色キーを常時表示
- **サイドパネル**: ヘッダ（クラスタ + レイヤバッジ） / 関数リスト / diff プレビュー
- **クラスタフィルタタブ**: 件数バッジ付き

## 7. インタラクション

### 確定
- ノードクリック → 詳細パネルに反映
- ホバー → 連結ノード以外をディム
- クラスタフィルタ → グラフ再構築
- 影響範囲モード切替（変更全体 / 選択起点）

### 未確定（要検証）
- ズーム / パン
- ノードドラッグでの再配置
- 検索（ファイル名 / 関数名）
- diff 行 → コード位置ジャンプ
- 影響範囲モードでの「壊れる可能性のあるテスト」抽出
- キーボードショートカット

## 8. 影響範囲の表現

hop 数で色と強調を段階化：

| Hop | ラベル | 表現 |
|---|---|---|
| 0 | 変更 | teal、ノード塗り |
| 1 | 直接影響 | 橙、点線リング |
| 2 | 2hop | 黄、薄い点線リング |
| 3+ | 遠い | 黄緑、最薄リング |
| なし | 影響なし | グレー、不透明度を下げる |

エッジも「両端ともに impact あり」のものだけ強調、それ以外は淡化。

## 9. Tweaks（ユーザー設定）

現在UI上で露出（★）+ 候補。

- ★ クラスタ色の表示 ON/OFF
- ★ レイヤラベル表示 ON/OFF
- ★ ノード密度（compact / comfortable / spacious）
- ★ サイドパネル位置（右 / 下 / オーバーレイ）
- グラフレイアウト切替（DAG / スイムレーン / force / radial）
- 分類軸の差し替え
- テストノードの表示有無
- エッジ種別フィルタ
- ダーク / ライト

## 10. 用語（UI上で使う日本語）

| 用語 | 意味 |
|---|---|
| モジュール | 解析単位（≒ファイル） |
| クラスタ | 4分類（追加/削除/修正/リファクタ） |
| レイヤ | UI/Domain/Data/Infra |
| エッジ | 依存関係 |
| hop | 影響範囲の段数 |
| 影響範囲 | 変更が伝播する可能性のあるモジュール集合 |
| 依存元 | 自分に依存している側（影響を受ける） |
| 依存先 | 自分が依存している側（影響を与える） |
